# Рефлексия: ReTracker — ImageViewer, режим 3D-наклона и прозрачные PNG

## Метаданные
- Дата: 2026-03-31
- Уровень сложности: 2
- Задача: Опциональный «красивый» просмотр изображения в полноэкранном ImageViewer — изначально планировался параллакс-сдвиг; в итоге реализован псевдо-3D (perspective + rotateX/Y), доработаны иконка и отображение PNG без фона.

## Резюме
В `ImageViewer.jsx` добавлен переключаемый режим с отслеживанием мыши: родитель с `perspective`, внутренняя обёртка с `preserve-3d`, трансформ через DOM (`rotateX`/`rotateY`, `translateZ`, лёгкий `scale`) и rAF+lerp. Режим отключается при добавлении комментария и при `prefers-reduced-motion`; кнопка скрыта при reduce motion. После обратной связи пользователя: иконка заменена на «куб» (объём); для прозрачных PNG убран градиентный блик с `mix-blend`, тени переведены на `drop-shadow`; то же для превью изображения в `CommentAttachments.jsx` (`FilePreviewOverlay`).

## Что прошло хорошо
- План Level 2 совпал по духу (один главный компонент, без бэкенда); отклонение от текста плана (3D вместо translate) улучшило UX без расползания scope.
- Трансформ на DOM-уровне на внутренней обёртке сохраняет синхрон пинов/аннотаций с картинкой и избегает перетирания `transform` React при обновлении `style` родителя.
- Быстрые итерации по UX: иконка и прозрачность после короткой обратной связи.

## Сложности
- Первый вариант (только translate) не совпал с ожиданием «псевдо-3D» — решено переходом на наклон плоскости и перспективу.
- Градиентный оверлей в 3D давал визуальный «фон» на альфе PNG — решено удалением оверлея; `box-shadow` заменён на `drop-shadow` для более естественного контура у прозрачных изображений.
- Нужно помнить: при сильных фильтрах + `transform` возможны редкие артефакты в отдельных браузерах — пока не зафиксировано.

## Уроки
- Для изображений с альфой избегать **светлых** оверлеев с **mix-blend** поверх всего кадра — они заполняют прозрачные области.
- Для тени у PNG предпочтительнее **`drop-shadow`** вместо **`box-shadow`**, если важен силуэт непрозрачных пикселей.
- Текст плана можно уточнять после первого просмотра прототипа (3D vs «параллакс» — разные ожидания у пользователя).

## Улучшения процесса
- Для визуальных «приколюх» в плане Level 2 заранее вкладывать слова вроде «tilt / псевдо-3D» или скрин-референс, чтобы сократить итерацию.
- При следующем подобном фиче можно вынести хук `usePointerTilt` + константы, если появится второй потребитель.
