# Рефлексия: Скетч (рисование) в чате задачи

## Метаданные
- Дата: 2026-04-01
- Уровень сложности: 3
- Задача: Новая функция "Скетч" в чате задачи ReTracker — рисование на чистом холсте, отправка как PNG

## Резюме
Создан `SketchEditor` — полноэкранный редактор для рисования с нуля. Добавлена кнопка "Скетч" в меню вложений (`AttachmentMenu`). Интегрировано в `CommentInput` через существующий `addBlobFile`. Рисунок отправляется в чат как обычное PNG-вложение.

## Что прошло хорошо
- **Переиспользование паттернов** — форк `ImageAnnotationEditor` позволил быстро получить рабочий canvas-движок (drawing, undo/redo, export) без дублирования сложной логики
- **Существующая инфраструктура** — `addBlobFile` → `uploadSingleFile` → `task-files` bucket → `comments.attachments[]` работает из коробки, ноль новых эндпоинтов/таблиц
- **Чистая интеграция** — всего 3 точки изменения: новый компонент, +1 пункт меню, +1 state в CommentInput
- **Консистентный UI** — тот же layout (top bar + left toolbar), те же emerald акценты, те же иконки/курсоры
- **Упрощение** — убрали всё лишнее из ImageAnnotationEditor (фигуры, текст, стрелки, overlay canvas), получился компактный и понятный компонент (~280 строк vs ~720)

## Сложности
- Минимальные — задача хорошо ложилась на существующую архитектуру

## Уроки
- **Паттерн "blob → addBlobFile → chat"** — универсальный и может использоваться для любых генерируемых клиентом медиа (скетчи, аннотации, скриншоты и т.д.)
- **Canvas-компоненты стоит проектировать как форки** — общий базовый движок рисования можно было бы вынести в shared модуль, но для двух компонентов это over-engineering
- **Выбор фона холста** — решён через CSS-фон контейнера + экспорт с fillRect, а не через рисование фона на canvas. Это позволяет менять фон на лету без перерисовки

## Улучшения процесса
- Creative phase для такого уровня задачи (один UI-компонент с чётким аналогом) можно делать ещё компактнее — решение было очевидным
